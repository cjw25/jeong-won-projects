# 브라우저 검증 체크리스트 — 안심 한 걸음

이 문서는 기능을 직접 확인할 때 사용할 절차입니다. **아직 이 환경에서 브라우저를 실행해 테스트한 결과가 아닙니다.** 실행하지 않은 항목은 통과했다고 기록하지 마세요.

## 테스트 전 주의사항

- 비밀번호 재설정·결제·초대 링크 등 개인 토큰이 포함될 수 있는 주소, 실제 문자, 계정 정보는 입력하지 마세요.
- 아래 예시 주소만 사용하세요. 분석기는 주소를 열지 않지만, 개인 링크 자체를 입력창에 붙여넣지 않는 것이 안전합니다.
- 분석 결과는 일부 주소 형식 신호일 뿐입니다. 경고가 없다고 안전한 링크라는 뜻은 아닙니다.
- 개발자 도구의 네트워크 확인은 선택 항목입니다. 사용 중인 브라우저가 다르면 메뉴 이름이 다를 수 있습니다.

## 1. 화면과 자동 점검

| ID | 확인 방법 | 기대 결과 |
| --- | --- | --- |
| UI-01 | `index.html`을 브라우저에서 열고 페이지가 준비될 때까지 기다립니다. | 자동 점검 목록이 초기 안내에서 실제 결과로 바뀝니다. `file://`로 열면 로컬 파일 안내가 나오며, HTTPS 웹 주소로 배포했다면 HTTPS 안내가 나옵니다. |
| UI-02 | `지금 다시 확인`을 누릅니다. | 점검 결과가 다시 표시되고 완료 시각이 갱신됩니다. 시각 변경까지 확인하려면 몇 초 기다렸다가 누릅니다. |
| UI-03 | 브라우저 저장 공간 점검 결과를 읽습니다. | 임시 저장·확인 후 삭제 성공 또는 저장을 사용할 수 없다는 안내 중 하나가 나옵니다. 어느 경우에도 개인 정보를 입력하지 않습니다. |
| UI-04 | 상단의 `링크 분석`, `긴급 대응`, `자동 점검` 메뉴를 차례로 누릅니다. | 해당 화면만 표시되고 현재 메뉴가 구분됩니다. 화면 전환 뒤 키보드 초점이 화면 제목으로 이동하는지도 확인합니다. |

## 2. 링크 분석

각 주소는 **링크 분석 입력란에만** 입력하고 분석 버튼을 누르세요. 결과가 나와도 주소를 직접 열지 마세요.

| ID | 입력 예시 | 기대 결과 |
| --- | --- | --- |
| LINK-01 | `https://example.com` | HTTPS 사용 안내와 함께 추가 형식 경고가 없다고 표시합니다. 결과에 안전 보장 아님을 알리는 한계 설명이 보입니다. |
| LINK-02 | `http://example.com` | 암호화되지 않은 HTTP 경고가 나옵니다. |
| LINK-03 | `https://user:pass@example.com` | 주소에 사용자 정보가 있다는 경고가 나옵니다. 결과 화면에는 사용자 이름·비밀번호·경로·쿼리가 표시되지 않는지 확인합니다. 예시의 `user:pass`는 가짜 문자열입니다. |
| LINK-04 | `https://192.0.2.1` | 도메인 대신 IP 주소를 사용한다는 경고가 나옵니다. 이 예시 주소를 열지는 마세요. |
| LINK-05 | `https://bit.ly/example` | 알려진 단축 도메인 형식이라는 경고가 나옵니다. 최종 이동 주소를 확인했다고 표시하지 않아야 합니다. |
| LINK-06 | `https://example.com:8443` | 기본값이 아닌 포트 경고가 나옵니다. |
| LINK-07 | `ftp://example.com` | HTTP/HTTPS 이외의 주소로 거부됩니다. |
| LINK-08 | `javascript:alert(1)` | 웹 주소가 아니라고 거부됩니다. 페이지 이동이나 코드 실행이 일어나지 않아야 합니다. |
| LINK-09 | `주소가 아님` | 주소 형식 오류 안내가 나옵니다. |
| LINK-10 | 임의의 예시 주소를 분석한 뒤 `입력과 결과 지우기`를 누릅니다. | 입력창과 결과가 초기 안내로 돌아가고, 입력창에 초점이 놓입니다. |

선택적으로 다음도 확인할 수 있습니다.

- `https://xn--e1afmkfd.example`처럼 `xn--`로 시작하는 도메인 레이블이 있는 문자열에서 다국어 도메인 안내가 나오는지 확인합니다. 이 예시 역시 열지 마세요.
- 체크박스에서 메시지의 주의 신호를 선택·해제하면 안내가 바뀌고, 신호가 없다고 안전하다는 뜻은 아니라는 내용이 유지되는지 확인합니다.

## 3. 기본 점검 표시와 저장

| ID | 확인 방법 | 기대 결과 |
| --- | --- | --- |
| CHECK-01 | 기본 보안 항목 하나를 `완료로 표시`로 바꿉니다. | 진행률이 `1 / 4 완료`로 바뀌고 버튼 상태도 완료로 표시됩니다. |
| CHECK-02 | 페이지를 새로고침합니다. | 브라우저 저장소를 사용할 수 있는 경우 완료 표시가 유지됩니다. 사용할 수 없는 경우 앱의 안내와 일치하는지 확인합니다. |
| CHECK-03 | `완료 표시 초기화`를 누르고 확인합니다. | 모든 항목의 완료 표시와 진행률이 초기화됩니다. 취소를 누르면 기존 표시가 유지되어야 합니다. |

## 4. 개인정보·네트워크 확인 (선택)

1. 브라우저 개발자 도구의 **Network(네트워크)** 탭에서 기록을 지운 뒤 임의의 예시 주소를 분석합니다.
2. 분석 버튼을 누른 결과로 입력한 호스트나 외부 평판 조회 서비스에 새 요청이 생기지 않는지 살펴봅니다. 앱 파일을 처음 불러오는 요청과 링크 분석 시 발생하는 요청을 구분하세요.
3. 개발자 도구의 저장 공간 화면에서 점검 완료 표시만 저장되는지 확인할 수 있습니다. 임시 점검용 항목 이름은 `__ansim_hangeoreum_probe_`로 시작하며, 점검 뒤 남아 있으면 저장 공간 삭제 실패 안내가 표시되는지 확인합니다.
4. 다른 사이트의 저장 데이터나 브라우저 기록은 지우지 마세요. 개인 링크나 민감한 내용을 화면 캡처·보고서에 포함하지 마세요.

## 5. 접근성·화면 크기

- 마우스 없이 `Tab`, `Shift+Tab`, `Enter`, `Space`로 메뉴, 버튼, 링크 입력란, 펼침 항목을 조작합니다.
- 키보드 초점 표시가 보이고, 링크 입력란의 이름과 분석 결과를 읽을 수 있는지 확인합니다.
- 개발자 도구의 기기 모드나 창 크기를 사용해 폭 320~375px의 작은 화면과 데스크톱 화면을 확인합니다. 내용이나 버튼이 잘리거나 의도하지 않은 가로 스크롤이 생기지 않는지 살펴봅니다.
- 가능하면 브라우저 확대 200%에서도 주요 기능을 사용할 수 있는지 확인합니다.
